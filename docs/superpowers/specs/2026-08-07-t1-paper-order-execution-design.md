# T+1 虚拟订单与趋势验证账户 V2 设计

## 目标

消除当前虚拟盘在完整收盘信号产生后仍按同日收盘价成交的执行偏差。所有系统自动交易改为“两阶段”：T 日完整收盘数据生成订单，T+1 交易日按开盘价、现有不利滑点和交易费用成交。

本次同时建立干净的趋势验证账户 V2，使新的有效回合、收益、超额和回撤只来自可复现的 T+1 成交模型。旧趋势账户与全部历史永久保留、只读，不删除、不改写。

本次不改变候选排序、财务阈值、止损止盈幅度、持仓数量上限、ERP 规则、行业集中度或实盘准入回合数，也不连接券商。

## 适用范围

采用 T+1 订单模型的路径：

- 趋势仓自动买入和自动卖出；
- 深价仓自动分批加仓、恐慌买入、自动止损止盈和其他系统生成的自动订单。

不采用 T+1 订单模型的路径：

- `main.py trade` 人工记账命令。该命令表示用户已经在外部确认成交价格，继续即时写入对应虚拟账户；
- 候选池假设性买入追踪。它只用于观察，不进入账户订单队列。

## 两阶段日更流程

每次日更严格按以下顺序执行：

1. 使用交易日历确定最新完整交易日 T；日历不可判定时停止全部自动订单创建和成交。
2. 读取订单账本，先处理计划成交日不晚于 T 的历史待成交订单。
3. 使用订单计划成交日的日 K 开盘价作为基础价格：买入增加现有 0.1% 不利滑点，卖出减少现有 0.1% 不利滑点，再按现有费用模型计算佣金和印花税。
4. 只有成交成功后才修改虚拟账户、交易记录和净值。
5. 用 T 日收盘数据检查成交后的持仓、退出条件、深价自动加仓条件和趋势候选。
6. 新信号只创建下一交易日 T+1 的待成交订单，当天不得成交。
7. 保存账户、订单账本和报告。重复运行同一交易日必须幂等。

系统漏跑一天时，只要订单已在此前生成，就按原计划交易日的真实开盘行情复原其结果。这等价于订单已提前进入虚拟经纪队列，系统故障不得带来重新择时的优势。

## 订单账本

新增两个活动订单账本：

- `output/paper_orders.json`：深价仓自动订单；
- `output/paper_orders_trend_v2.json`：趋势验证仓 V2 自动订单。

每条订单至少包含：

```text
order_id
warehouse
code / name / direction / quantity
signal_trade_date / planned_trade_date
signal_reason / reference_close
status
attempts / last_block_reason
fill_trade_date / open_price / fill_price / fees
created_at / updated_at
```

允许的状态为：

- `PENDING`：等待计划成交日；
- `BLOCKED`：计划成交日已到，但数据不足、停牌或卖出受一字跌停阻塞；
- `FILLED`：已成交且已写入账户；
- `CANCELED`：买入不可成交、现金不足、人工交易改变仓位或订单失去可执行性。

订单历史不删除。状态终结后继续留在账本中，作为虚拟成交审计依据。

`order_id` 必须可稳定去重。同一仓、同一股票、同一方向最多存在一笔 `PENDING` 或 `BLOCKED` 订单；同日重复运行不得重复挂单、扣费、成交或记录净值。

## 现金、仓位和冲突规则

- 买单生成时固定数量，并按参考收盘价、滑点和预计费用预留现金；其他待买订单不得重复使用这部分现金。
- 趋势仓的待买订单计入最多 5 只的仓位数量约束。
- 开盘跳空导致实际资金不足时，买单取消，不临时缩量或借用未来卖出款。
- 待卖订单优先于同票待买订单；存在活动卖单时禁止新建同票买单。
- 不提前使用次日卖出所得资金创建买单。卖出成交后，最早在当日收盘重新产生买入信号，并于下一交易日成交。
- 全部退出订单在成交时卖出该股票当前剩余数量，避免人工部分卖出后自动订单超卖。
- 固定数量的部分卖出订单不得超过当前持仓；持仓不足时取消并记录原因。
- 人工交易改变仓位后，所有不再可执行的自动订单必须取消并保留审计原因。

## 停牌、涨跌停和数据异常

- 买入在计划日遇到确认的一字涨停：取消。未来必须由新的收盘信号重新生成订单，不追逐过期信号。
- 买入计划日行情暂时缺失：标记 `BLOCKED`，数据恢复后复核原计划日；若确认停牌或不可成交则取消。
- 卖出遇一字跌停或停牌：标记 `BLOCKED`，以后每个交易日继续尝试，直至出现可成交日。
- 卖出数据暂时缺失：保持 `BLOCKED`，不得猜测成交价或把失败包装成无信号。
- 交易日历不可判定、K 线缺少计划日期、价格非法或费用计算异常：fail-closed，不修改账户。

一字板继续复用项目现有的日 K 近似：开盘价、最高价和最低价相等，且方向不利。仅开盘触及涨跌停但当日打开时，按开盘价和滑点成交。

## 趋势验证账户 V2

新增活动文件：

```text
output/account_trend_v2.json
output/trades_trend_v2.csv
output/performance_trend_v2.csv
output/paper_orders_trend_v2.json
```

V2 初始虚拟资金为 200 万元，初始持仓为空。原 `account_trend.json`、`trades_trend.csv`、`performance_trend.csv`、旧订单及历史报告保持只读。

趋势日更切换到 V2。旧趋势账户不再产生订单，日报只显示一行“旧成交模型历史仓快照”。双策略活动组合改为“深价活动仓 + 趋势 V2”，旧趋势账户不计入活动组合收益。

V2 继续使用当前冻结的趋势策略参数。初次运行可以按现有策略产生多笔待买订单，但不得在创建当天成交。

## 有效验证与准入

- V2 创建交易日是新的有效验证切点；旧账户交易和表现不得进入 V2 指标。
- 有效完整回合、收益、基准收益、超额和最大回撤只读取 V2 账户与表现文件。
- 首次审查日取 `2027-01-01` 与 V2 启动满 6 个月两者中的较晚日期。
- 即使提前达到 30 个完整回合，也不得提前进入实盘讨论。
- 原有准入条件保持：有效完整回合至少 30、有效累计超额大于 0%、有效最大回撤大于 -50%、达到最早审查日。
- 系统只允许输出“可讨论 50 万元小额实盘”，不自动连接账户、不自动转实盘、不保证盈利。

## 日报与审计输出

新版日报增加以下明确分区：

```text
## 今日虚拟成交
## 下一交易日待成交
## 受阻/取消订单
## 趋势验证仓 V2
## 旧趋势模型历史仓
## 有效验证仪表板
```

每笔成交显示：信号日、计划成交日、实际成交日、参考收盘价、开盘价、滑点后价格、费用、隔夜跳空影响和成交原因。

无成交也必须显示零值；受阻和取消必须显示具体原因，不能写成“今日无信号”。

## 实现边界

订单状态机和价格计算应提取为独立模块，负责：

- 创建与去重订单；
- 计算下一交易日；
- 判断订单是否到期；
- 使用注入的日 K 行情决定成交、受阻或取消；
- 返回结构化结果。

模块不得直接扫描候选或决定策略阈值。`auto_trader.py` 只负责把现有信号转换为订单，并消费订单执行结果更新账户，避免把订单状态继续堆进交易策略主流程。

本次不重构账户类、不迁移旧账户结构、不删除旧文件、不修改人工交易语义。

## 测试与验收

新增标准库单元测试和临时目录集成测试，至少覆盖：

1. T 日信号不得同日成交；
2. T+1 买卖分别按开盘价和不利滑点成交；
3. 佣金、印花税和成交金额使用实际成交价；
4. 开盘跳空真实计入盈亏；
5. 现金不足时买单取消且账户不变；
6. 一字涨停买单取消；
7. 一字跌停卖单保持并在后续可成交日完成；
8. 停牌和行情缺失 fail-closed；
9. 交易日历异常时不创建、不成交；
10. 重复运行不重复挂单、成交、扣费或记录净值；
11. 待买订单预留现金并占用趋势仓位名额；
12. 卖单优先、买卖冲突和人工交易后的订单取消；
13. 深价人工交易仍即时，深价自动交易全部延后；
14. 旧趋势账户及历史文件哈希不变；
15. V2 初始资金、空仓、订单和首日净值正确；
16. V2 有效回合、表现和审查日期不读取旧账户；
17. 日报完整展示成交、待成交、受阻、取消、V2、旧仓快照和验证仪表板；
18. 全量测试数不得少于实施前的 61 项，零跳过。

验证不得运行活动账户日更。使用临时账户、构造交易日历和构造 K 线完成红灯—绿灯测试；实施完成后不自动创建 V2 活动状态。第一次受控日更必须单独汇报预计产生的订单并取得用户许可。

## 上线与仓库状态

当前本地 `master` 与远端存在分叉：本地领先多个功能提交，远端独有一笔 `2026-08-06` 自动日更。实现和验证完成后，必须先按单独批准的整合方案处理远端历史，禁止自动 rebase、强推或覆盖远端。

远端合并与推送成功前，GitHub Actions 仍运行旧流程。不得为了验证本设计而手动触发远端日更。

## 风险与代价

- T+1 跳空、不成交和费用会降低纸面收益，但这是消除不可实现成交的必要代价。
- 新增订单状态和 V2 文件会扩大代码、测试和运维复杂度。
- V2 从空仓重新开始，短期收益与样本归零，达到 30 个完整回合可能需要更久。
- 旧趋势持仓不再进入活动组合，用户需要同时区分活动 V2 与只读历史仓。
- 当前趋势信号的质量问题不会在本次修复中改变；V2 可能机械产生对高负债或低基数反转公司的订单，这是冻结策略接受未知数据检验的结果。
- 本设计提高成交与验证可信度，不提高策略收益，也不构成盈利保证。
