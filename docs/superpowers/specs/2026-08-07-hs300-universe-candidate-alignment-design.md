# 沪深300股票池与趋势候选生成对齐设计

## 目标

修复趋势仓候选稀缺的两个上游口径错误：沪深300成分获取失败后把全市场缓存冒充正式股票池，以及先截取改善幅度最高 TOP10、再由交易端淘汰全部基数噪音。保持现有策略阈值不变，使纸上测试重新使用文档规定的沪深300母集。

## 现场证据

- `data/market/stock_universe.csv` 当前为 5,329 只、`index=全市场`，但 `CLAUDE.md` 与 `config.yaml` 均规定沪深300。
- `scan_trend_improvement()` 对该缓存按代码顺序取前300只，不是沪深300。
- 2026-08-07 保存的趋势 TOP10 全部改善超过500pp，交易漏斗因此 10→0。
- 本地财务缓存中存在大量改善 5–500pp 且满足既有 ROE、当前利润同比条件的股票；候选为0不是市场事实。

## 股票池规则

1. 正式股票池只接受满足以下条件的数据：
   - 列包含 `code`、`name`、`index`；
   - 代码去重后数量在 250–350；
   - 每行 `index` 均为“沪深300”。
2. 网络取得的新成分股只有通过验证后才能原子替换正式缓存。
3. 当前缓存若是“全市场”或数量异常，不得直接返回，也不得作为有效兜底。
4. 网络失败时，仅允许返回上次有效沪深300缓存。为避免错误缓存覆盖最后正确版本，正式缓存自身就是最后有效版本；无有效缓存则返回明确的不可用状态/空表。
5. 不再把全市场列表写入 `stock_universe.csv`。需要全市场研究时必须使用独立文件和入口，本次不新增。

## 趋势候选规则

1. 扫描母集来自已验证的沪深300股票池，最多按配置扫描300只。
2. 在截取 TOP10 前应用交易端已有的基础质量条件：
   - 改善幅度 5–500pp；
   - ROE ≥ 6%；
   - 当前利润同比 ≥ -20%。
3. 负债率、52周高点、商品周期、冷却期等现有后置规则保持原位置和口径，不提前改变。
4. 合格结果按改善幅度降序取前 `n` 只；输出同时报告扫描数、各前置过滤数量和最终候选数。
5. 股票池不可用时不覆盖现有 `trend_candidates.csv`，日报明确显示“候选刷新冻结”。

## 测试与验收

新增测试覆盖：

1. 300只且全部标记沪深300的缓存通过；
2. 5,329只全市场缓存被拒绝；
3. 网络异常时使用最后有效沪深300缓存；
4. 无有效缓存且网络失败时返回不可用，不写全市场缓存；
5. TOP10 在截取前过滤 >500pp、<5pp、ROE<6%、当前同比<-20%；
6. 至少15个基数噪音排在前面时，后续合格股票仍能进入TOP10；
7. 全量测试数不减少、零跳过。

不运行自动交易作为单元测试。实施完成后单独运行一次受控日更，验收输出必须同时满足：股票池约300只且标记沪深300；趋势漏斗不再因“TOP10全是>500pp”结构性归零。若真实沪深300当天确实没有合格候选，允许最终为0，但必须由完整漏斗证明。

## 风险与代价

- 指数成分接口与有效缓存同时不可用时会停止候选刷新，可能错过当日机会。
- 候选池纠正后会改变未来纸上测试的入场样本；这是恢复既定沪深300口径，不是调参，但应在变更日志中记录切点。
- 当前错误全市场缓存不直接删除；成功取得并验证沪深300后由原子替换覆盖，避免手工删除触碰用户数据。
- 本修复提高验证有效性，不保证交易数量或盈利。
