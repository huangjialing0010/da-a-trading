# 虚拟盘自动日更可靠性设计

## 目标

提高虚拟盘验证样本的可重复性和可信度，防止旧缓存、依赖漂移、测试失败或并发执行污染账户状态。

本次只加固 GitHub Actions 虚拟盘日更流程，不修改选股、买卖、仓位和实盘准入参数，不连接券商，也不启用实盘。

## 已确认问题

1. 工作流使用不存在的 `github.run_date`。GitHub Actions 会将不存在的属性解析为空字符串，导致缓存键退化为固定的 `market-data-`。
2. `actions/cache` 当前恢复整个 `data/`，可能将旧缓存回填到 Git 已跟踪的 `data/market/`，影响沪深300股票池、交易日历和基准行情。
3. 缓存是不可变的；固定键首次保存后不会随每日运行更新。
4. 工作流没有并发控制，定时运行和手动运行可能同时修改虚拟账户并竞争提交。
5. 依赖使用无版本约束的 `pip install`，第三方升级可能改变行为或导致日更失败。
6. 日更前不运行测试，代码故障可能直接写入虚拟账户和验证报告。
7. `data/daily_kline/` 当前约 678 MB，且文件名包含行情截止日期，跨交易日复用价值低，不适合每天上传完整 Actions 缓存。

## 设计决策

### 1. 固定运行环境

新增根目录 `requirements.txt`，固定当前已通过本地测试的版本：

```text
akshare==1.18.64
pandas==3.0.3
numpy==2.5.1
PyYAML==6.0.3
```

工作流改为 `python -m pip install -r requirements.txt`。Python 版本继续固定为 3.12。

### 2. 日更前置验证

安装依赖后、恢复业务缓存后，先执行：

```bash
python -m unittest discover -s tests -v
```

任何测试失败都必须终止作业，禁止调用 `daily_update()`，因此不会写入虚拟账户、报告或市场数据。

### 3. 缓存边界

缓存只允许包含：

- `data/financials/`
- `data/sw_index/`

明确禁止缓存：

- `data/market/`：这里包含已跟踪、会影响交易判断的权威数据。
- `data/daily_kline/`：体积大且跨日期复用收益低。
- `output/`：包含账户、交易和报告状态，必须以 Git 中的最新状态为准。

缓存键包含操作系统、Python 版本、依赖文件哈希和本次运行 ID；恢复键使用不含运行 ID 的前缀，以恢复最近一次可信缓存并在成功后保存新缓存。按当前数据量，每次约 19 MB；代价是产生滚动缓存并占用少量 Actions 存储。

### 4. 防止并发写账户

工作流增加固定并发组 `da-paper-daily`，并设置 `cancel-in-progress: false`。同一时刻只允许一个日更运行，避免两个进程并行写虚拟账户。

GitHub 对同一并发组只保证一个运行中和有限待处理运行；若短时间内连续多次手动触发，较早的待处理运行可能被替换。因此该机制用于防重叠，不作为任务队列。

### 5. 数据流与失败规则

执行顺序固定为：

1. 检出默认分支最新提交。
2. 设置 Python 3.12。
3. 按锁定版本安装依赖。
4. 恢复非权威业务缓存。
5. 运行全部单元测试。
6. 测试通过后执行一次 `daily_update()`。
7. 只暂存 `output/` 和 `data/market/`。
8. 有变化才提交并推送；无变化正常结束。

任一步失败都停止后续步骤。不得通过忽略错误、`continue-on-error` 或跳过测试来维持日更。

本次不加入自动重试、自动 rebase、强制推送或券商接口。推送遇到非快进冲突时保持失败，交由人工诊断，避免自动改写历史或合并不确定状态。

## 验证标准

实施完成后必须满足：

- YAML 可解析，工作流不再引用 `github.run_date`。
- 缓存路径不包含 `data/market/`、`data/daily_kline/` 或 `output/`。
- 工作流在 `daily_update()` 前运行全部测试。
- 工作流存在固定并发组且不取消正在运行的日更。
- 依赖安装只使用固定版本的 `requirements.txt`。
- 本地执行全部测试通过，测试总数不得少于修改前的 57 个。
- 不实际触发 GitHub Actions，不运行本地 `daily_update()`，不新增虚拟交易。
- 工作区最终只包含获批范围内的工作流、依赖清单、测试和文档改动。

## 风险与代价

- 不缓存日线数据会增加每日网络请求和运行时间，预计仍在现有 45 分钟超时内，但数据源波动时可能失败。
- 固定依赖提高可重复性，但需要以后主动评估和升级，否则会错过兼容性或数据源修复。
- 前置测试增加几分钟运行时间；换来的好处是错误代码不能直接污染虚拟账户。
- 并发锁防止同时写入，但不能保证大量手动触发全部排队执行。
- GitHub 定时任务仍可能延迟或被平台丢弃；本设计不承诺每个交易日绝对执行，只保证实际执行时的状态边界更可靠。
- 这些措施只提高验证质量，不提高策略收益，也不构成盈利保证。
